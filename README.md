# AI Client Brief Generator

Инструмент для автоматического превращения текстовых материалов клиентского диалога в структурированный PDF-отчет на русском языке.

Проект ориентирован на русскоязычные бизнес-сценарии и формирует PDF-отчеты с корректной кириллицей, датами и бюджетами в рублях.

Это компактный локальный CLI-инструмент: нет базы данных, веб-сервера, Docker или CI/CD — только Python-скрипт, который читает `.txt`-файл, обращается к OpenAI и сохраняет PDF локально.

---

## Приватность и передача данных

**Важно понимать, прежде чем использовать проект с реальными данными:**

- Исходный `.txt`-файл — это только локальный входной файл. Вся его текстовая обработка происходит не «локально»: **полный текст диалога отправляется в настроенную модель OpenAI** (см. `OPENAI_MODEL` в `.env`) для извлечения структурированных данных. Локального/офлайн AI-режима у проекта нет.
- Не отправляйте в обработку конфиденциальную, персональную, регулируемую (например, ПДн, медицинские, финансовые данные) или иную защищенную информацию клиента без соответствующего разрешения и согласия клиента.
- Для портфолио, демо и учебных материалов рекомендуется предварительно обезличить (редактировать) диалог: заменить реальные имена, названия компаний, телефоны и т.д. на вымышленные.
- Проект не хранит и не передает данные никуда, кроме OpenAI API. PDF и изображения сохраняются только локально, в `reports/` и `generated_images/`.

## Режимы работы

### `client_report` — Отчет по клиентскому запросу

Универсальный режим для любого типа клиентского диалога. Извлекает: суть запроса, проблемы и потребности клиента, требования к решению, сроки, бюджет, риски и следующие шаги.

```bash
python main.py example_dialogs/ai_bot_client_dialog.txt --mode client_report
```

### `design_report` — Отчет по дизайн-запросу с изображением

Режим для диалогов о разработке сайта или лендинга. Дополнительно извлекает: цель дизайна, целевую аудиторию, визуальные предпочтения, основные блоки сайта и функциональные требования. По умолчанию также генерирует AI-изображение с визуальной концепцией.

```bash
python main.py example_dialogs/website_design_dialog.txt --mode design_report
```

Генерация изображения — это **отдельный, потенциально платный запрос** к image API (модель задается через `IMAGE_MODEL` в `.env`, по умолчанию `gpt-image-2`; реальная доступность модели зависит от вашего OpenAI-аккаунта). Prompt для визуальной концепции формируется автоматически на основе диалога и используется только внутри системы — в итоговом PDF он не отображается.

Чтобы пропустить генерацию изображения и не делать запрос к image API вовсе:

```bash
python main.py example_dialogs/website_design_dialog.txt --mode design_report --no-image
```

PDF в этом случае формируется как обычно, с placeholder-блоком вместо изображения. Если image API не настроен или запрос завершился ошибкой (и флаг `--no-image` не указан), текстовый PDF все равно будет сформирован — с тем же placeholder-блоком.

Проверить доступность моделей и подключение к image API можно командой `python main.py --test-image` (подробнее об этой команде — в разделе «Все команды» ниже).

### `client_brief` — технический alias

`client_brief` сохранен как alias для `client_report` — старые команды не ломаются:

```bash
python main.py example_dialogs/ai_bot_client_dialog.txt --mode client_brief
```

## Как проект получает данные

Проект **не подключается напрямую** к CRM, Telegram, Google Docs или другим сервисам — такой интеграции нет и не планируется в рамках этого репозитория. Единственный источник данных — локальный `.txt`-файл с транскрибацией или текстовыми материалами.

Как получить файл:

- **Zoom / Google Meet** — скачать автоматическую транскрибацию из записи встречи.
- **Telegram** — скопировать переписку в `.txt`.
- **Диктофон / телефонный звонок** — расшифровать через Whisper, Yandex SpeechKit или другой сервис, сохранить как `.txt`.
- **CRM** — экспортировать историю переписки или комментарии к сделке.

После этого положить файл в папку `input_dialogs/` и запустить генерацию.

**Ограничение на размер файла:** входной файл не должен превышать 120 000 символов (модест, практичный предел для расшифровки одного диалога). Проверка выполняется локально, до какого-либо обращения к OpenAI — при превышении лимита программа завершается с ошибкой и запрос не отправляется.

## Требования

- Python 3.11+
- [API-ключ OpenAI](https://platform.openai.com/api-keys)
- Системные зависимости WeasyPrint (см. ниже)

Версии зависимостей, протестированные в рамках этого проекта, зафиксированы в `requirements.txt`:

- `openai==2.41.0`
- `jinja2==3.1.6`
- `weasyprint==69.0`
- `python-dotenv==1.2.2`

### Системные зависимости WeasyPrint

**Windows** — установите [GTK3 Runtime](https://github.com/tschoonj/GTK-for-Windows-Runtime-Environment-Installer/releases), затем перезапустите терминал. Альтернатива — WSL.

**macOS**:
```bash
brew install pango gdk-pixbuf libffi cairo
```

**Ubuntu / Debian**:
```bash
sudo apt install libpango-1.0-0 libpangoft2-1.0-0 libcairo2 libgdk-pixbuf2.0-0
```

> **Про шрифты.** HTML-шаблоны запрашивают шрифт **DejaVu Sans** с fallback на Arial и Segoe UI (`"DejaVu Sans", "Arial", "Segoe UI", sans-serif`). WeasyPrint сам по себе шрифты не поставляет — он использует шрифты, установленные в системе. Реально используемый шрифт и качество отображения кириллицы зависят от того, что доступно в вашей системной конфигурации шрифтов (fontconfig на Linux/macOS, системные шрифты на Windows). Если кириллица отображается некорректно, установите DejaVu Sans (или любой другой шрифт с полной поддержкой кириллицы) в системе.

## Установка

```bash
cd ai-client-brief-generator

python -m venv .venv

# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

Для разработки и запуска тестов используйте `requirements-dev.txt` (включает `requirements.txt` и `pytest`):

```bash
pip install -r requirements-dev.txt
```

## Настройка

```bash
cp .env.example .env
```

Откройте `.env`:

```dotenv
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o

# Для режима design_report:
IMAGE_MODEL=gpt-image-2      # тестовый/дефолтный вариант проекта
IMAGE_SIZE=1024x1024         # 1024x1024 | 1536x1024 | 1024x1536
IMAGE_QUALITY=medium         # low | medium | high | auto

LOG_LEVEL=INFO
```

`gpt-4o` — это протестированная модель по умолчанию для извлечения структурированных данных в этом проекте, а не универсальная рекомендация «лучшей» или «последней» модели OpenAI. `gpt-image-2` — аналогично, конфигурация по умолчанию для генерации изображений; реальная доступность моделей зависит от вашего OpenAI-аккаунта/project — проверяйте через `python main.py --test-image`, а не полагайтесь на название модели.

## Все команды

### Диагностика генерации изображений

```bash
python main.py --test-image
```

Выполняет **реальный, потенциально платный** запрос к image API с текущими настройками из `.env`. При неудаче выводит точную ошибку от OpenAI, статус-код и список моделей, доступных на вашем аккаунте.

### Посмотреть список доступных файлов

```bash
python main.py --list-files
```

### Интерактивный выбор файла и типа отчета

```bash
python main.py --interactive
```

Программа покажет все `.txt`-файлы, предложит выбрать файл, затем — тип отчета.

### Отчет по клиентскому запросу

```bash
python main.py example_dialogs/ai_bot_client_dialog.txt --mode client_report
python main.py input_dialogs/my_dialog.txt --mode client_report
```

### Отчет по дизайн-запросу с AI-изображением

```bash
python main.py example_dialogs/website_design_dialog.txt --mode design_report

# Без генерации изображения (без запроса к image API):
python main.py example_dialogs/website_design_dialog.txt --mode design_report --no-image
```

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Не задан API-ключ | Подсказка с инструкцией по настройке `.env` |
| Файл не найден | `[ERROR] Файл не найден: <путь>` |
| Путь указывает на папку | `[ERROR] Указанный путь не является файлом: <путь>` |
| Файл не в UTF-8 | `[ERROR] Не удалось прочитать файл как UTF-8` |
| Файл пустой | `[ERROR] Файл пустой: <путь>` |
| Файл превышает лимит размера (120 000 символов) | `[ERROR] Файл слишком большой: <путь> (...)` — запрос к OpenAI не выполняется |
| OpenAI вернул невалидный JSON или не прошел валидацию схемы | `[ERROR] OpenAI вернул некорректный или неполный ответ` — PDF не формируется |
| Модель image API недоступна | Точная ошибка + список доступных моделей, PDF формируется без изображения |
| PDF заблокирован (PermissionError) | `[ERROR] Не удалось сохранить PDF. Возможно, файл уже открыт.` |

### Устранение ошибки Permission denied на Windows

Если при генерации PDF появляется ошибка `Permission denied`:

- Убедитесь, что файл отчета не открыт в просмотрщике PDF (Adobe Acrobat, браузер и т.д.).
- Проект создает уникальные имена файлов с секундами, но открытый файл может быть заблокирован Windows.
- Закройте PDF-просмотрщик и повторите запуск.

## Тестирование

Полный набор тестов — офлайн, без реальных обращений к OpenAI:

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Тесты покрывают: валидацию схем ответов модели, обработку файловых ошибок, сборку запроса к OpenAI (таймаут/ретраи/лимит токенов — на моках), рендеринг HTML-шаблонов (экранирование), генерацию PDF через реальный WeasyPrint-рендерер, генерацию изображений (на моках) и именование выходных файлов.

## Ограничения

- **Передача данных в OpenAI.** Полный текст диалога отправляется в OpenAI для обработки — локального AI-режима нет (см. «Приватность и передача данных» выше).
- **Стоимость.** Каждый запуск делает как минимум один платный запрос к Chat Completions API. В режиме `design_report` без флага `--no-image` также выполняется отдельный, дополнительный платный запрос к image API. `--test-image` тоже платный.
- **Размер входного файла.** Ограничен 120 000 символами на один диалог (см. «Как проект получает данные»).
- **Только локальный CLI.** Нет веб-интерфейса, CRM-, Telegram- или иной интеграции — только чтение локального `.txt` и сохранение PDF/изображений в локальные папки `reports/` и `generated_images/`.
- **Отсутствие персистентного состояния.** Проект не хранит историю запусков, базы данных или очередей — каждый запуск независим.
